# Avatar 行为生成系统 — 设计概述

## 我们要做什么

让一个虚拟角色（avatar）能根据语言指令自主做出动作。从"LLM 说了一句话"开始，到"角色在屏幕上动起来"结束。

不考虑 LLM 怎么获取外部信息（那是 agent 的事），也不考虑动画播放到具体平台的工程适配（比如 VRChat 需要模拟 VR 手柄输入）。

---

## 设计原则

**像人脑一样分层。** 整个系统分四层，灵感来自运动神经科学里的分层运动控制——前额叶负责决策，基底节负责选择动作模式，脊髓的 Central Pattern Generator 负责自动执行，感觉系统提供空间反馈。

**先搭管道，再选模型。** 不是先选定某个动作生成模型再围绕它搭系统，而是先定义好每一层之间传递数据的格式（接口），让整条数据流跑通。模型是可以随时替换的零件。

**纯运动学，不做物理仿真。** 物理仿真器会让动作过于"物理正确"，反而产生机器人式的僵硬感。人的动作恰恰不是物理最优的——有犹豫、有惯性浪费、有个人风格的微小不对称。这些在物理优化器看来是"误差"，在观感上却是让人看起来像人的关键。所以动作生成模型直接输出骨骼旋转，不经过力矩和接触力计算。空间感知用简单的碰撞体和几何计算替代物理引擎。

---

## 第一层：决策（LLM）

对应前额叶皮层。低频率，只在需要决策时介入。

一个大语言模型，根据对话内容和场景信息，生成一份结构化的"行动计划"。计划由一系列"技能节点"组成，每个节点说明：

- 要执行什么技能（走路、坐下、挥手……）
- 参数是什么（走多快、朝哪走、用哪只手）
- 什么时候算完成（到达目标、姿态稳定、超时、被打断）
- 依赖哪些前置节点（先走到椅子旁边，才能坐下）

计划是短期的、一次性的。环境变了或者用户说了新的话，LLM 直接生成一份新计划整个替换旧的，不做增量修改。

为了防止 LLM 反复生成失败的计划（比如一直尝试开一扇锁着的门），每次重新规划时会附带最近的执行历史——哪些技能成功了、哪些失败了、失败原因是什么。

规则：计划必须以一个"永远不会自行结束"的技能收尾（比如待机或闲逛），确保角色永远不会僵住。

---

## 第二层：调度（工作流运行时）

对应基底节 + 运动皮层。负责把决策层的计划变成生成层能执行的具体指令。

这一层做三件事：

1. **推进计划**：按照依赖关系依次执行技能节点，检查每个节点的完成条件
2. **编译指令**：把"走路，速度正常，朝椅子走"这样的语义描述，翻译成动作生成模型能理解的多模态指令
3. **管理动作切换**：在两个动作之间选择合适的过渡方式

### 技能库

技能库是决策层和调度层之间的契约，定义了 LLM 可以使用哪些技能词汇，以及每个技能对应什么样的动作生成指令。

每个技能有类型之分：
- **周期性技能**（走路、跑步）：像 limit cycle attractor，不给停止信号就一直执行
- **一次性技能**（坐下、挥手）：像 point attractor，执行完自然收敛到终态

### 多模态指令

动作生成模型不应该只接受文字描述。"走到椅子旁边"这个指令，光靠文字很难精确传达空间信息。所以我们定义了一个统一的多模态指令格式（ConditioningSpec），可以同时包含：

- 文字描述（"一个人正常速度走路"）
- 空间目标（目标位置坐标、朝向）
- 轨迹引导（路径点序列）
- 过渡提示（从什么技能切换到什么技能、过渡时长）

不同的动作生成模型能消费的指令类型不同。模型启动时会声明自己支持哪些类型（能力握手），调度层会自动把不支持的类型降级为文字描述。比如某个模型不支持空间目标，"走到坐标 (10, 0, 0)"就会被降级为"向前走很远"。

### 动作切换

从一个动作切换到另一个动作是个核心难题。Diffusion model 的概率分布在两个动作模式之间存在低概率沟壑（BeyondMimic 论文的核心发现），直接跨越容易失败。

我们的策略不是禁止模型跨越，而是让调度层和生成模型协作——调度层知道"要从什么切换到什么"（语义级），生成模型知道"具体怎么执行这个切换"（动力学级），调度层通过过渡提示给模型提供"路标"。

三种过渡方式：

1. **直接切换**：适用于语义上本身就是断裂的（站着突然坐下），依赖模型的自回归特性保证连续性
2. **惯性插值（Inertialization）**：适用于需要平滑过渡的（走路变跑步）。记录切换瞬间每个关节的位置和速度，用弹簧-阻尼系统把差异衰减到零。这是 3A 游戏的工业标准做法，保证切换时的动量守恒感
3. **过渡技能**：在两个动作之间插入一个专门的过渡动作（走路 → 减速停步 → 坐下）

## 第三层：生成（动作生成模型）

对应脊髓的 Central Pattern Generator。高频自动执行，一旦进入某个动作模式就不需要上层持续干预。

接收多模态指令，持续输出骨骼动画帧。输出格式是统一的"动作帧"（MotionFrame）：每一帧包含根节点的世界坐标位置和旋转，以及所有关节相对于父骨骼的局部旋转（四元数）。

不同模型有不同的适配器，负责把模型原生输出转换成统一的动作帧格式。

### 模型选型

选型标准按优先级：纯运动学 > 多模态指令支持 > 自回归/流式输出 > 跨模式切换能力。

目前的候选：
- **PRIMAL**：可插拔的 ControlNet 架构，指令类型最灵活，是最终目标模型
- **DART**：超过 300fps 的推理速度，支持文字 + 空间控制，自回归，高性能候选
- **FloodDiffusion**：快速原型验证用
- **Mocap 回放**：早期阶段用录制好的动作片段验证管道

---

## 第四层：空间感知

不是物理仿真器，而是一个轻量的空间查询工具。

角色需要的"物理"其实是几何计算：
- 不穿墙不穿家具 → 碰撞体 + 射线检测
- 知道离目标多远 → 距离计算
- 脚不穿地板 → 地面高度约束
- 手碰到物体 → 球体/胶囊体重叠检测

这些用基本碰撞体就能做到，不需要物理引擎。

### 脚部接触修正

纯运动学模型的常见问题是脚滑和脚浮。空间感知层用轻量的 Two-Bone IK 修正：从脚踝向下打射线找到真实地面高度，计算偏移量，调整膝盖角度保持脚底贴地，必要时把臀部往下拉。纯几何约束求解，和物理引擎完全不是一个量级。

### 空间查询对动作引导的支持

空间感知层的查询结果可以作为动作生成模型的引导信号输入——比如"离障碍物的距离"可以转化为避障代价函数。这让模型有能力做空间感知的运动调整，而不需要物理仿真器。

---

## 反馈机制

事件驱动的异步反馈，不是每帧都同步检查。生成层大部分时间自主运行，只在特定事件发生时上报：

- 到达目标 → 调度层推进到下一个技能
- 目标不可达（长时间没有接近） → 通知决策层重新规划
- 超时 → 调度层强制推进
- 碰撞 → 空间感知层自行修正，严重时上报

大部分事件由调度层自行处理，只有异常才上报决策层触发重新规划。

---

## 两个核心接口

整条管道的稳定性取决于两个接口定义：

1. **ConditioningSpec**（调度层 → 生成层）：统一的多模态指令格式，包含文字、空间、轨迹、过渡提示
2. **MotionFrame**（生成层 → 空间感知层 → 角色）：统一的每帧骨骼数据格式

这两个接口稳定后，生成模型和空间感知层都是可以随时替换的零件。

---

## 技术选型

- 角色格式：VRM（纯正向运动学驱动，没有反向运动学干扰）
- 渲染：Three.js + @pixiv/three-vrm
- 骨骼映射：SMPL-X 轴角 → 四元数 → 直接写入 VRM 骨骼（坐标系一致，不需要翻转）
- 空间感知：Three.js 基本碰撞体，不需要物理引擎
